Nexus Companion Console

Compact always-on-top Electron window for the Nexus Interstellar Traffic System. It pairs a live event feed, split into three categories, with an active mission readout and a pinned radio strip. This page is the working reference for the build. The window on the left is interactive: switch tabs, expand rows, tune, transmit, and use the simulate buttons to see new events arrive.

Anatomy, top to bottom

1 Titlebar30px. Custom frame. Drag region. Pin (always on top), compact toggle, hide to tray. 2 Operator headerName, rank label, three stat readouts (Crew RP, Ship RP, Missions). 3 Mission barOnly rendered while the operator is on an active mission. Click to expand. Holds Complete and Abort. 4 Category tabsMissions, Crew, Ships. No "All" tab. Missions is the default. Unread badge per tab. 5 FeedFlexible height, scrolls. Rows expand in place for detail. 6 Radio stripCyan "RADIO" signal label with a live dot, the saved push-to-talk key shown at right, then frequency LCD, tune down and up, and transmit toggle. Always visible, including while chat is open. 7 Chat barFull-width button at the very bottom with an unread badge. Opens the direct message panel in place of the tabs and feed.

Each incoming socket event is routed to exactly one tab. A row inserted into an inactive tab raises that tab's badge, which clears when the tab is opened. A row inserted into the active tab animates in at the top of the feed.

Typeface: Inter, a plain sans serif, for everything in the window (weights 400 to 700, tabular numerals for the timer and frequency). Minimum text size is 10px, body text 11 to 13px. No text glows or shadows. Monospace appears only in this spec's code samples. The app is a single dark theme with no light mode.

Depth system

  • Window slab: stacked hard shadows below the frame (2px, 4px, 6px steps in darkening blues) plus a soft 40px drop shadow, a 1px top highlight inside, and a faint blue ambient glow.
  • Raised card: vertical gradient #0F2338 to #0A1828, 1px inside top highlight, 3px hard under-edge #050e18, soft drop shadow. On hover it lifts 1px.
  • Button: same recipe with a 3px under-edge. On press it translates down 3px and the under-edge collapses to zero, so it reads as a physical key.
  • Active tab: pressed state. It sits 2px lower with a brighter fill and a blue outer glow.
  • Icons: radial gradient discs with an inner top highlight, tinted by event color.
  • No window motion: the window stays flat and fixed like a normal app. No tilt, no cursor glow, no sheen. Depth comes only from the static shadows and bevels above.

Behavior

  • Tabs: single select, Missions on launch. Last selected tab persists between sessions.
  • Feed rows: click toggles a detail panel with a 280ms height transition. Multiple rows may be open at once.
  • Mission bar: expands to show commander, objective, crew, and Complete and Abort. Each button needs a two-step confirm (first click changes the label to "Confirm", second click fires). The preview shows only the first step.
  • Radio: tune steps of 0.1 MHz between 130.0 and 139.9, wrapping. TX toggles transmit and turns the LCD red.
  • Push-to-talk shortcuts: the app keeps every shortcut the player has set in the web app version. It reads the same saved keybindings and registers them as global shortcuts (globalShortcut or a low-level key hook for hold-to-talk), so they work while Star Citizen has focus. The key shown beside the RADIO label always reflects the saved binding. The preview uses F8 as a stand-in: hold it to transmit.
  • Direct messages: any player name anywhere in the window (feed rows, mission detail) is clickable and opens a direct message thread with that player. Names show a dotted underline and turn lime on hover. The Chat button opens the thread list (newest first, unread dot per thread). Within a thread: back arrow, close, bubbles, text input, Enter to send. Incoming messages raise the unread badge on the Chat button. Your own name is never linked. Direct messages only for now; global chat stays out of scope.
  • Pin: toggles always on top. Pinned state persists.
  • Compact mode: collapses the window to titlebar, mission bar, and radio strip only (about 150px tall). Hides tabs and feed.
  • Reduced motion: all transitions are disabled under prefers-reduced-motion.

Electron notes (proposed)

  • Window: 340 × 540, min 340 × 150, resizable in height only, frame: false, backgroundColor: '#000710'.
  • Always on top: setAlwaysOnTop(true, 'screen-saver') so it stays above a borderless fullscreen game. Note that exclusive fullscreen will still hide it.
  • Drag: the titlebar uses -webkit-app-region: drag; the three titlebar buttons use no-drag.
  • Tray icon with show, hide, and quit. The close button hides to tray.
  • Renderer reuses the Nexus frontend stack (React, socket.io-client) and talks to the existing backend on port 3099 through the same /api and /socket.io routes.
  • Persisted settings in the main process: window position, pinned, compact, selected tab, opacity.

Open questions

  • Should the Missions tab also let the user browse and join open missions, or stay a pure event feed?
  • Is a window opacity slider wanted, for sitting over gameplay?
  • Should offline operators appear in the Crew feed, or only come-online events?
  • Where does the web app store push-to-talk bindings today? If only in browser storage, the backend needs to persist them per user so the Electron app can read them.
  • Does a direct message system exist in the backend yet, or does it need new models, routes and socket events?
