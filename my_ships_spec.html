My ships, implementation specification

Option A, grouped list, with the motion set. The live demo below is the visual and behavioral source of truth. Sections after the demo give measurements, data rules, motion variables, edge cases and a verification checklist. Everything here is a design target. Where the real data model or existing handlers differ, keep the real ones and report the difference. The ship image and node map are placeholders.

1. Scope

This specification covers the My ships tab only. Ship Registry is a separate task. A ship is either On mission or Available, so the list has two groups. Confirm in the data model that no third status exists. If one does, add a group for it using the same header pattern and report it.

4. Data and text rules

group order        On mission, then Available. Empty groups are not rendered.
within a group     most recently registered first (confirm with the owner)
count chip         total ships across both groups
stat line          done > 0  ? done + " missions · " + fill + "% avg fill"
                   done == 0 ? "No missions yet"
avg fill tile      fill == null ? "–" : fill + "%"
status text        On mission | Available (colors: amber | lime)
meta               Type, Registered (YYYY-MM-DD), Owner (display name)

Avg fill is the average crew fill rate across the ship's completed missions. It should use the same crew-fill definition as the mission board, filled slots divided by total slots. Do not compute it a new way. If the app already has this value, display it.

Field names are not confirmed. Look up the real fields for ship name, manufacturer and model, type, registered date, owner, status, completed missions, average fill and lifetime RP before wiring. Do not infer them from this mockup.

7. Interaction rules

EventSequence
Select shipDisarm any delete. Cancel edit mode. Move the stripe. Fade old detail blocks out over 90 ms, swap content, then rise each block in over 280 ms with 40 ms stagger. Map settles from 98.5 percent over 420 ms. Numbers count up over 420 ms. Enter and Space also select a focused card.
Edit nodesGrid overlay fades in over 280 ms. Node rings scale from 40 to 100 percent with overshoot, 40 ms stagger, and pulse every 1.6 s. The action group cross-fades to Save and Cancel over 280 ms. Save and Cancel both leave edit mode. Escape cancels.
Live missionMeasure the live face. Ease height to it over 420 ms. Ship face slides 26 px left with 2 px blur and fades. Live face slides in from 26 px right. Rows rise 8 px with 38 ms stagger after a 120 ms offset. Back reverses the slide. Escape goes back.
Delete, step oneButton grows from 30 to 184 px over 280 ms, turns red, and shows Confirm delete with a number counting down from 8. A 2 px bar under the label empties linearly over 8 s.
Delete, step twoA second press inside the 8 s window deletes. The card fades, slides 12 px right and collapses over 240 ms. The next ship selects with the standard ship switch.
Delete, disarmAny of these shrinks the button back over 280 ms: the 8 s expiring, Escape, selecting another ship, opening live view, entering edit mode, or a click anywhere outside the button. The timer and the number reset each time it is armed.
Delete, failureIf the server refuses the delete, restore the card with the reverse of the exit, shake the button 300 ms, and show the error message in the app's usual toast.
Register shipExisting registration flow runs unchanged. When the new ship appears, its card drops in 8 px over 280 ms with a lime wash fading over 700 ms, then it selects.
Mission start or endRealtime status change. The card exits its group over 240 ms and enters the other with the same wash. If it is the selected ship, the status text glows for 700 ms. The beat runs only while On mission.
Group headerClick collapses or opens the group. Remember each group's state per user.
Back to dashboardPane dims to 15 percent over 160 ms, then the existing navigation runs.

8. Edge cases

  • Last ship deleted. Show one muted line, "No ships registered yet." and give the Register ship button a gold outline.
  • Many ships. The list scrolls. Group headers stay sticky. Selected card scrolls into view on selection.
  • Selection after delete. Next ship in the same group, else the first ship in the list.
  • Live mission when Available. Disable the button and show the tooltip "Not on a mission". Confirm this with the owner, since the current screen shows it always enabled.
  • Edit nodes while On mission. Keep the current rule. Do not change who may edit.
  • Long names. Card names and models truncate with ellipsis and carry the full text in the title attribute.
  • No history text. Show a muted line, "No history yet."
  • Delete while live view is open. The delete button is not in the live face, so this cannot occur.

9. Accessibility

  • Cards are buttons. The selected one has aria-current="true".
  • Group headers are buttons with aria-expanded.
  • The delete button announces "Delete vessel. Press again within 8 seconds to confirm." through a polite live region when armed, and "Delete cancelled" when disarmed.
  • The countdown number is visible text, so it works without motion.
  • Back buttons carry aria-labels. Icon-only buttons carry title attributes.
  • Focus returns to the control that opened a view when that view closes. Focus ring is 2 px gold.
  • Reduced motion drops every duration to near zero and numbers jump to their final value. The 8 s delete window stays, because it is a safety delay and not an animation.

10. Verify before building

  • List the real ship statuses. Confirm there are only two, or add a group per extra status.
  • Find the real field names for crew slots, completed missions, average fill and lifetime RP.
  • Find the existing handlers for edit nodes, live mission, delete and register. Reuse them. Wrap, do not rewrite.
  • Check that the live mission view can be shown inside the same pane. If it is a separate route today, report that and keep the slide for the route change.
  • Check whether Ship Registry shares this card component. If so, build the component once and keep this spec as the My ships variant.

11. Acceptance

  • Two groups render with correct counts, sticky headers and collapse.
  • Selecting a ship runs the staggered swap and counts the numbers up.
  • Edit nodes shows the grid, popping rings and the Save and Cancel swap.
  • Live mission slides in and out and the height eases without a jump.
  • Delete needs two presses inside 8 s, shows the ticking number, and disarms on every trigger in section 7.
  • Register and mission status changes animate as described.
  • No horizontal overflow at 1000 px wide or at 400 px wide. Below 700 px the left panel stacks above the detail.
  • Reduced motion is honored.
